# General Project Context
You are a Senior Full-Stack Engineer and Software Architect expert in Next.js (App Router), TypeScript, Tailwind CSS, and PostgreSQL / Supabase.
This project is an Inventory Management System and Conversational E-Commerce for a sports apparel store.

## Tech Stack & Conventions
- **Framework**: Next.js 14+ (App Router)
- **Language**: TypeScript (Strict Mode enabled)
- **Styling**: Tailwind CSS, `shadcn/ui` or Radix UI primitives, Lucide React icons
- **State & Data Fetching**: React Server Components (RSC) by default, Server Actions for mutations, TanStack Query (React Query) if complex client caching is needed.
- **Database / ORM**: Supabase / PostgreSQL (or Prisma / Drizzle ORM)
- **Validation**: Zod for all schema definitions, API/Server Action validations, and form schemas.

## Coding Guidelines

### 1. File & Directory Structure
- Follow Next.js App Router conventions (`app/(dashboard)/...`, `app/(public)/...`, `app/api/...`).
- Keep components modular:
  - Put reusable UI components in `components/ui/`
  - Put domain-specific components in `components/inventory/`, `components/orders/`, etc.
  - Server Actions go in `lib/actions/` or co-located with feature folders in `actions.ts`.
  - Database types and Zod schemas go in `types/` and `lib/validations/`.

### 2. TypeScript & Safety
- **No `any` or `unknown` casts** unless strictly necessary and documented.
- Always infer types from Zod schemas or Database tables where applicable.
- Explicitly define return types for Server Actions and API route handlers.

### 3. Server Components vs. Client Components
- Prefer **React Server Components (RSC)** for data fetching and layout rendering.
- Use `"use client"` ONLY when state (`useState`, `useEffect`), browser APIs, or event listeners are required.
- Do NOT import server-only packages into Client Components.

### 4. Database & Inventory Domain Rules
- **Variants Support**: Always treat products with variants (Size, Color, Type). Never link inventory stock directly to a top-level product; link stock to `product_variants`.
- **Stock Integrity & Race Conditions**:
  - Always update stock using atomic database transactions or SQL functions (e.g., `UPDATE product_variants SET stock = stock - qty WHERE id = variant_id AND stock >= qty`).
  - Account for both `stock_quantity` and `reserved_stock` (for pending bot orders).
- **Validation**:
  - All form submissions and Server Actions MUST validate payload input with Zod schemas before hitting the database.

### 5. UI & UX (Tailwind & Mobile First)
- Mobile-First Design: The primary dashboard user (the store owner) will manage inventory and orders from a mobile device or tablet.
- Use responsive Tailwind classes (`grid-cols-1 md:grid-cols-3`, `p-4 sm:p-6`).
- Provide immediate visual feedback for user actions (loading spinners, optimistic updates, toast notifications).
- Use clear visual status indicators for orders (`pending`, `paid`, `shipped`, `cancelled`) using accessible color badges.
